Italian Radar DPC VIL product¶

Live-updated composite Weather Radar Vertically Integrated Liquid (VIL) precipitation product (kg/m²), providing continuous spatial coverage over the Italian peninsula from July 2018 to the present.

The dataset is stored in Zarr format with a pre-allocated time dimension spanning July 2018–2050. Only a subset of this range contains valid observations; all remaining time steps are filled with NaN values. The temporal extent of valid data is demarcated by the last_valid attribute of the Zarr dataset: all time steps up to and including this timestamp contain valid observations, while all subsequent time steps are empty. Consumers of this dataset should query this attribute to determine the current data availability before performing any analysis. Note also that the spacing of the time axis is not constant over the whole archive (for example the Italian radar products moved from a 10-minute to a 5-minute cadence in July 2018), so never compute a position from the start of the series and a nominal step: always look timestamps up on the time coordinate, e.g. ds.sel(time=ds.attrs['last_valid']) or ds.indexes['time'].get_loc(...).

Data caveat — value encoding (2019-08-01 06:50 -> 2025-10-08 09:30)¶

A subset of the files in this archive store vertical maximum intensity quantized onto a 0.5-unit grid (values fall on 0.0, 0.5, 1.0, 1.5, …), which is inherent to the source product and not an artefact of our processing. However, a smaller subset of these files was processed by the CIMA Foundation using a different encoding convention for the two "empty" cases: inside the radar coverage domain, pixels with no echo were written as 0.5 rather than 0, while pixels outside radar range — which have no measurement at all — were written as 0. This inverts the intuitive reading of the data: a naive arr == 0 mask on the original CIMA files selects the un-observed region, not the observed-but-dry one. To make the archive internally consistent, we have reprojected these files to the archive's native projection and remapped the values so that 0.5 inside radar range becomes 0 (no echo) and everything outside radar range becomes the archive's NoData value. As a concequence, because 0.5 was the lowest non-zero bin, any pixel that legitimately measured 0.5 inside the radar domain in a CIMA-processed file is now indistinguishable from a true zero and has been collapsed into it; the affected timesteps therefore have a slightly inflated zero fraction and a missing 0.5 bin relative to the non-CIMA files. The period is indicated in the heading.

var_name = "vil"

# Cartopy projection from the dataset's CF grid mapping
gm = ds[ds[var_name].grid_mapping].attrs
data_crs = ccrs.TransverseMercator(
    central_longitude=gm["longitude_of_central_meridian"],
    central_latitude=gm["latitude_of_projection_origin"],
    scale_factor=gm["scale_factor_at_central_meridian"],
    false_easting=gm["false_easting"],
    false_northing=gm["false_northing"],
)

g = ds[var_name].sel(time=['2026-08-17T13:00', '2026-08-17T14:00', '2026-08-17T15:00']).plot(
    col="time", transform=data_crs, subplot_kws={"projection": data_crs},
    cmap=cmap, vmin=0.5, vmax=20,
)
for ax in g.axs.flat:
    ax.coastlines("50m")
